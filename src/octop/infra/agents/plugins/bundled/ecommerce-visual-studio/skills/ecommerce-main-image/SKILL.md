# 电商主图与场景图

把一张商品实拍图，变成可直接上架的主图或场景图。

## 零、出图只能走内置工具（先读这条）

出图**必须**调用内置的 `generate_image` 工具。这是唯一一条会把图片交付给用户的路径——
工具返回的图片由媒体管线接管，会自动出现在对话里。

**绝对不要做的事：**

- ❌ 自己写 Python 脚本调图像 API、`httpx` 下载、`provider.submit_image(...)`
- ❌ 从 `~/.octop/octop.db` 读 `media_generation_config_v2`、解密 `secrets` 里的 api_keys
- ❌ 自己拼输出目录名（例如 `ref.stem[-13:]`、`stem.split("_")[-2]`）再 `send_file_to_user`

**为什么**：凡是你自己写出来的图，都落在工作区里、不受媒体管线管理。路径只要差一个字符
（参考图名 `1791821440_微信图片_2026101301014_181_1.png` 用 `stem[-13:]` 会截成
`3001014_181_1`，丢掉前半段），用户收到的就是一句 "no such file" 或一条空回复——
**你干完了活，但用户那边看到的是一片空白**，还以为你在空烧 token。

**看不到 `generate_image` 怎么办：**

1. 它可能以「延迟引用」形式出现，描述末尾带 `[Deferred reference: call tool_search before use.]`
   → 先调 `tool_search` 把 `generate_image` 载入，再调用它。
2. 如果确实不存在，说明**媒体生成没有启用**（或当前会话是在启用前开的）→ 告诉用户去
   「设置 → 模型 → 生成模型」打开开关并重开会话。
3. **无论哪种情况，都不要自己造轮子。** 宁可停下来问，也不要写脚本——写脚本的代价是
   每轮重发数万 token，而且最终交付不出去。

**正确做法**：收图 → 写 prompt → `generate_image(prompt=..., reference_images=[图], size=..., count=4, watermark=False)`
→ 自检 → 用**工具返回的**图片交付。

出图本身用内置的 `generate_image` 工具。本技能负责的是**怎么把这件事做对**——
尤其是下面第一条红线。

## 一、首要红线：商品本体必须保真

电商主图和普通 AI 绘图最大的区别：**买家收到的东西必须和主图一致**。
主图把商品改样了，换来的是退货、差评和平台处罚。

**绝对不许改变的部分：**

- 商品的颜色、材质、纹理、光泽
- 形状、比例、结构（按键位置、镜头开孔、接口、卡扣）
- 品牌 logo、文字、型号标识的**内容与拼写**
- 包装、配件、赠品的种类与数量

**可以自由发挥的部分：**

- 背景与场景
- 光线方向与色温
- 镜头视角与景深（前提：不改变商品结构）
- 氛围道具（必须是陪衬，不能抢主体、不能与商品混淆）
- 整体色调与风格

**操作要求：**

- 一律把商品图放进 `reference_images`，不要只靠文字描述商品。
- prompt 里先写"保持参考图中的商品**完全不变**"，再描述场景。
- 出图后**逐张自检**：颜色对不对？logo 拼写对不对？形状有没有被改？
  **有任何一项不对就重出，不要交付。**
- 涉及 logo / 文字时，明确告诉用户"AI 对文字还原不稳定，请务必人工核对"。

## 二、出图流程

> **一句话前提：电商主图 = 商品图 ＋ 卖点文案。只有商品、没有文案的图，不叫主图。**

1. **收图** —— 要商品原图。没有原图就先要，别硬凭描述生成（必定不像）。
2. **拿到卖点（硬前置，不能跳）** —— 先看参考图能推断出什么（品类、颜色、材质、配件），
   再按下面顺序补齐：
   - 用户已经说了卖点 → 直接用。
   - 商品标题 / 需求描述里有 → 提炼成 1–2 条短语。
   - **都没有 → 停下来问用户**："这件商品的核心卖点是什么？（防摔？容量？材质？续航？）"
     **不要自己编功效**（防摔/防水/亲肤这类写错就是虚假宣传），
     **也不要拿"新品上架""品质之选"这种废话充数**——那不是卖点。
3. **问清其余三件事**（能从上下文推断的就别问）：
   - 目标平台（淘宝 / 京东 / 拼多多 / 抖音 / 亚马逊）
   - 场景意向（棚拍白底 / 居家 / 户外 / 办公 / 节日）
   - 数量（**用户说了就照做**，没说才默认 4 张）
4. **组装 prompt** —— 按第三节写画面部分，**并把卖点文案按第四节写进去**
   （原文 + 层级 + 位置 + 字体 + 颜色 + 质量要求）。**文案和画面一次性生成**，
   不要让模型先出无字图再想办法补字。
5. **出底图** —— `generate_image`，带 `reference_images`，`count` 按用户要求。
6. **把文案写进 prompt（必做）** —— 按第四节：文案原文 + 层级 + 位置 + 字体 + 颜色
   + 质量要求，让**模型连同画面一起渲染**。**没有文案就没有交付物。**
7. **自检** —— 商品按第一节核对；**文案做 OCR 复检**，有错字就重出。
8. **交付** —— 用叠好文案的成品图交付，说清：卖点是什么、几张、什么规格。

## 三、Prompt 结构

按这个顺序写，模型理解最稳：

```
[保真声明] + [主体描述] + [场景] + [光线] + [镜头] + [风格] + [约束]
```

**示例（手机壳 → 夏日户外场景主图）：**

> 严格保持参考图中手机壳的颜色、材质纹理、镜头开孔位置与品牌标识完全不变。
> 主体是一只哑光液态硅胶手机壳。场景为夏日户外木质桌面，背景有虚化的绿植与
> 暖阳光斑。光线为下午三四点的侧逆光，柔和带轻微轮廓光。微距商品摄影，
> 浅景深，主体居中偏下，画面上方留出文案空间。杂志质感，干净高级。
> 不改变商品形状与颜色，不添加任何文字，不出现人手。

**要点：**

- **场景要具体**："夏日户外木质桌面**有虚化绿植**" 远好于 "户外"。
- **光线一定要写**：没有光线描述，出图会平、会像贴图。
- **留白是为了叠字，不是审美目的**：留出的空白区**必须**在第四节被卖点文案填满。
  空着交出去等于没做完。
- **一次只改一件事**：迭代时别同时换场景又换光线，否则无法归因。
- **负向约束写清楚**：`不添加文字`（**仅指这一步，你稍后自己叠**）、
  `不出现人手`（除非要手持效果）、`不变形`、`不改变颜色`。

### 用户说要"吸睛"时，别给"极简干净"

"极简留白 + 性冷淡" 是**品牌官网**的调性；主图要在信息流里和几百张图抢点击，
**极简等于没存在感**。用户说"吸睛""要点击率""有冲击力"时：

- **放大主体**：商品占画面 60–75%，不要缩在中间一小块。
- **制造对比**：深色商品配亮底 / 亮色商品配深底 / 冷暖对冲。
- **加视觉钩子**：强投影、悬浮感、水花/飞溅、光斑、动态模糊。
- **文案要大**：卖点字高占画面 1/6 以上，敢用粗黑体，敢加色块底衬。
- **给一个焦点**：一张图只讲一个卖点，别把五个卖点全塞进去。

反过来说，用户明确要"高级""简约""品牌感"时，才走留白克制的路线。
**先听用户的调性，再定构图。**

风格模板与更多可直接套用的写法见 `references/style-library.md`。

## 四、文案：让生图模型直接画上去（首选做法）

> ⚠️ **平台决定要不要文案——别套错。** 本技能包里还有一套 Amazon 专用技能
> （`product-shots-*`），它们强调"主图不能有任何文字"。**那条规则只对亚马逊成立**：
> 亚马逊主图禁止文字/角标/水印，是平台硬性规定。
> **淘宝 / 天猫 / 京东 / 拼多多 / 抖音 恰恰相反——没有卖点文案的主图基本没人点。**
> 先确认平台，再决定叠不叠字；国内平台一律要。

**文案是画面的一部分，不是贴纸。** 把中文文案**写进 prompt**，让生图模型连同商品、
背景、光线一起渲染出来——字和画面共用同一套光影、透视与景深，才像一张成品主图。

**本机实测**：中转站的 `gpt-image-2.5` 渲染中文**完全正确**。实测 prompt
「上方粗黑体大字『军工级防摔』，下方小字『1.5米跌落无损 · 亲肤不沾灰』，
中文字必须清晰、笔画完整、无错字、无乱码」→ 出图字字正确、笔画完整、排版规整。

**所以不要因为"AI 画中文会错"就不让它画**——那是老黄历。**首选永远是模型直出。**

### 怎么写进 prompt

明确给出这六项：

1. **文案原文** —— 用引号逐字写出，一个字都不要含糊
2. **层级** —— 哪个是大标题、哪个是副标题、字号比例
3. **位置** —— 上方居中 / 左上 / 画面下三分之一
4. **字体风格** —— 粗黑体 / 无衬线 / 圆体
5. **颜色** —— 纯白 / 深色 / 与底色强对比
6. **质量要求** —— `中文字必须清晰、笔画完整、无错字、无乱码`

**模板：**

> 画面上方三分之一为**粗黑体中文大标题「军工级防摔」**，纯白字；
> 标题正下方一行**小字「1.5米跌落无损 · 亲肤不沾灰」**，相同字体，字号约大标题的 1/3。
> 中文字必须清晰、笔画完整、无错字、无乱码方框。

### 交付前必须 OCR 复检

模型偶尔会把某个字写错。用 OCR（或你自己的视觉能力）核对：

- 字对不对？笔画完整吗？有没有多字 / 少字 / 乱码方框？
- **发现错字就重出**（在 prompt 里强调那个字、或换更粗的字体描述），不要交付。

### 兜底：模型连续两次都写不对时，才退回 PIL

只有当**同一句文案连续两次渲染错误**时，才退回 PIL 叠加：让模型出**留白**的底图
（prompt 写「画面上方留白，不要出现任何文字」），再用 `execute` + PIL 把字画上去。

这条路**永远不会有错字**，但字是"贴"上去的、不参与画面光影，**观感明显不如模型直出**
——所以它是**兜底方案，不是首选**。不要一上来就走它。

## 五、平台规格

> 各平台规则会变，**以平台最新要求为准**；下面是常用起点。

| 平台 | 主图建议 | 说明 |
|---|---|---|
| 淘宝 / 天猫 | 800×800 起，1:1 | 支持放大镜，图越大越清晰 |
| 京东 | 800×800 起，1:1 | 白底为主 |
| 拼多多 | 800×800，1:1 | 首图白底更容易过审 |
| 抖音 | 1:1 或 3:4 | 竖图信息流占屏更大 |
| 亚马逊 | 2000×2000，1:1 | 白底（RGB 255,255,255） |

- 传 `size="1:1"` 或直接给像素（如 `"1024x1024"`）；不确定时留空，由运行时选默认。
- 详情页长图 / 竖版视频封面用 3:4。
- 细节规则（白底比例、牛皮癣限制、极限词）见 `references/specs.md`。

## 六、批量与挑选

- **数量以用户指令为准**：用户说"两张"就出两张，**不要改成四张**。只有用户没说数量时，
  才默认 `count=4` 让他挑。用户明确要几张就给几张——多给不是周到，是不听话。
- **要同款系列**：固定 `seed`，只改场景描述，出来的风格更统一。
- **整店套图**：同一套场景参数，**逐个商品多次调用 `generate_image`**（每次一个商品），
  保证店铺视觉一致。是多次调用工具，**不是写一个循环所有商品的脚本**——见第零节。
- 出图默认带水印，**上架用图务必 `watermark=false`**。
- 尺寸要规格化（800 / 1000 / 2000px）时，**先让工具出图**，再对已交付的图做处理；
  不要为了规格化就绕开工具自己下载。

## 七、迭代

用户说"再亮一点""背景换纯白"时：

- **只改一个变量**，其它原样保留，便于对比。
- 记得带上**同一张参考图**和**同一条保真声明**。
- 连续两三轮仍不满意，就换思路（换场景或换风格模板），别在同一个 prompt 上微调到底。

## 八、合规

- **不用极限词**：最好 / 第一 / 最便宜 / 国家级 等，主图和文案都不能出现。
- **不虚假宣传**：没有的赠品、功能、认证都不要画进去。
- **不侵权**：不生成他人品牌 logo、明星肖像、受版权保护的 IP 形象。
- **不画效果图冒充实拍**：涉及功效（如"防水"）时，画面要能真实反映商品能力。
- 生成的图**交付前必须人工复核**，AI 出图不能免检上架。

## 九、交付话术

出图后固定带这一句：

> 已生成 N 张（规格 X）。**请重点核对商品的颜色、材质、logo 拼写与结构是否与实物一致**；
> AI 对文字和细节的还原存在波动，上架前请人工确认。

这不是客套——是这条技能存在的理由。
